Purchase & Credits – data model + logic

This doc explains how a user’s payment turns into credits, and how credits turn into daycare applications in this codebase.

High-level flow (what “buy daycare” means here)

Buy = buy credits pack Use = submit auto-apply applications
  • User pays Stripe for an auto_apply_credits pack (default 30 credits).
  • On Stripe success, server grants credits into the user’s wallet (AutoApplyCredit).
  • When user clicks “Auto-Apply to N Daycares”, server creates one Application per daycare and consumes 1 credit per daycare.
  • So “how many daycares the user bought/used” is best measured by counting Application rows with source=auto_apply.

User

  • _id: used as userId string in other collections
  • email: unique
  • userType: parent/provider/employer/employee
Model: backend/src/schemas/UserSchema.js

Purchase (transaction record)

  • userId: string user id (from User _id)
  • status: pending/completed/failed/refunded/cancelled
  • paymentType: e.g. auto_apply_credits or report
  • stripePaymentId/paymentIntentId: Stripe PaymentIntent id
  • creditsGranted: how many credits were granted for this purchase
  • daycareIds: array of daycare ids from checkout metadata (may be partial / informational)
Schema: backend/src/schemas/PurchaseSchema.js

AutoApplyCredit (credits wallet)

  • userId: unique per user (1 wallet per user)
  • totalCredits, usedCredits, remainingCredits
  • grants[]: history of credit grants, includes paymentReference (Stripe PaymentIntent id)
Schema: backend/src/schemas/AutoApplyCreditSchema.js

Application (what got submitted)

  • userId
  • daycareId: the daycare applied to
  • source: auto_apply or manual
  • status: pending/viewed/follow_up/responded/accepted/rejected/withdrawn
Schema: backend/src/schemas/ApplicationSchema.js

Relationships (informal ERD)

User (_id)
  ├── Purchase.userId (many purchases per user)
  ├── AutoApplyCredit.userId (one wallet per user)
  └── Application.userId (many applications per user)

Application.daycareId -> Daycare (_id or Daycare.id)  [not enforced via ref]
Purchase.daycareIds[] -> daycare ids from checkout metadata (informational)
There are no Mongoose ref relations here; relations are “by convention” using string IDs.

Parent & Child data storage (schemas)

  • Parent profile is stored as a single User document in the users collection.
  • Child profile is stored inside the parent User document as an embedded array: User.children[].
  • Auto-Apply child details (the child info used for the submission) are stored per Application record (collection: applications) when source=auto_apply.
UserSchema (embedded children) – backend/src/schemas/UserSchema.js
childSchema:
  - name: string (optional)
  - age: number (required, 1..18)
  - specialNeeds: string (optional)

userSchema (selected):
  - email: string (unique)
  - firstName: string
  - lastName: string
  - userType: parent/provider/employer/employee
  - children: childSchema[]  <-- embedded inside User document
ApplicationSchema (auto-apply child fields) – backend/src/schemas/ApplicationSchema.js
applicationSchema (selected):
  - userId: string
  - daycareId: string
  - source: "manual" | "auto_apply"
  - status: "pending" | ...

auto-apply fields (required when source="auto_apply"):
  - childName: string
  - childDob: date
  - preferredStartDate: date
  - specialNotes: string (optional)

Where the logic lives

  • Stripe intent creation + Purchase upsert: backend/src/controllers/paymentController.js (createPaymentIntent())
  • Stripe success ⇒ grant credits + mark Purchase completed: backend/src/controllers/paymentController.js (handlePaymentSucceeded())
  • Consume credits + create Applications: backend/src/controllers/applicationController.js (submitAutoApplyApplications())

How to explain “how many daycares bought” to the user

  • Purchased credits: sum of Purchase.creditsGranted for paymentType=auto_apply_credits and status=completed.
  • Used daycares: count unique Application.daycareId where source=auto_apply for that userId.
  • Wallet truth for remaining credits: AutoApplyCredit.remainingCredits.
